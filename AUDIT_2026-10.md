# Production-readiness audit (2026-10-01)

Scope: the manual-send extension on `main` and the unmerged auto-update proposal in PR #52. Implementation is proposed in PR #53. This record tracks what was confirmed by source inspection versus what still requires browser testing.

## Confirmed defects addressed by PR #53

| Severity | Finding | Resolution |
| --- | --- | --- |
| Critical | `chrome.scripting.executeScript({func:createPageInfo})` serialized a function that called helpers outside its execution world. Clicking Send could fail with "Could not get page info" (#31, #48). | Self-contained extraction plus tab-metadata fallback; Node regression tests. |
| High | Permanent `<all_urls>` access for a destination selected by the user. | Runtime request scoped to that HA host; manual browsing uses `activeTab`. |
| High | Webhook ID stored in sync and rendered as ordinary visible text. | Local secret storage, legacy migration, masked field. Re-save on each browser after upgrade. |
| High | Saving required a HEAD probe even though HA automation webhooks accept POST. | Save validates configuration without contacting HA; Test sends a POST. |
| High | Popup preview used `innerHTML` with webpage data and a forbidden inline `onerror` handler. | DOM element creation, `textContent`, explicit image-error listener, protocol-limited link. |
| Medium | Undeclared `archiver` dependency prevented packaging. | Uses OS ZIP utilities, checks required files and fails on empty archive. |
| Medium | Release used a custom fine-grained PAT and did not enforce a quality gate. | Release-scoped `GITHUB_TOKEN`, manifest/tag consistency, CI check before uploading. |
| Medium | No executable automated regression tests or PR CI. | Node built-in regression tests and PR workflow. |
| Medium | Release checks contacted GitHub by default, contrary to broad privacy-language claims. | Explicit opt-in; documentation distinguishes HA POST, GitHub update API and public favicon fallback. |

## Remaining work before shipping as stable

1. **End-to-end verification:** Load the PR build in current Chrome and Edge. Verify page, selected text, link context menu, inaccessible-to-script tab, favicon fallback, localhost and external HA endpoints. Test permissions denied, revoked, regranted, and migration from a prior release. An accepted HTTP response is not proof an HA automation executed.
2. **PR #52 requires rework before merging:** Automatic tab collection has no user gesture; it cannot rely on the `activeTab` permission used for manual sends after this change. Require explicit persistent grants for the intended sites and explain what data leaves the browser. Clamp alarms to a documented supported minimum and handle sleep/restart/navigation safely. Offer a pause and sensitive-site exclusion mechanism before enabling periodic transmission.
3. **Developer toolchain:** `npm ci` currently reports advisories in legacy ESLint 8 transitive development dependencies. These are not packaged with the extension. Upgrade to a maintained ESLint version and update the lockfile in a dedicated tooling PR, then reassess `npm audit`.
4. **Legacy code:** The background `chrome.action.onClicked` path is unreachable while `default_popup` is defined; its intrusive in-page alert script can be retired after confirming no documented alternative installation depends on it.
5. **Operational hardening:** Verify ZIP installation from Actions and GitHub release, manual rollback and store-review requirements. Add browser-level integration tests if maintenance justifies the test environment.

## Release gate

Run `npm ci && npm run check` and review the CI artifact. Validate the install and a real Home Assistant webhook with both Chrome and Edge. Keep PR #53 in draft until browser integration checks pass. Do not imply that unit tests or an HTTP 200 confirm a complete HA automation delivery.
